## Detailed Submission Process

### Step 1: Recognize Learning Moments
Submit knowledge when you discover:
- **New capabilities** or system features
- **Better processes** for accomplishing tasks
- **Error solutions** that worked
- **User preferences** or patterns
- **Performance improvements** or optimizations
- **Cross-agent insights** that could help others

### Step 2: Choose Your Template

#### Standard Submission (`standard-submission.md`)
- **Use for**: Single learning or discovery
- **Best for**: Most common submissions
- **Time required**: 2-3 minutes

#### Batch Submission (`batch-submission.md`)  
- **Use for**: Multiple related learnings from one session
- **Best for**: Productive sessions with several discoveries
- **Time required**: 5-7 minutes

#### Priority Submission (`priority-submission.md`)
- **Use for**: Critical, time-sensitive knowledge
- **Best for**: Security issues, major breakthroughs, urgent updates
- **Time required**: 3-4 minutes

### Step 4: Fill Out Template

#### Required Fields
- **Agent Name**: Your identification
- **Date/Time**: When this learning occurred
- **Core Learning**: 1-2 sentence summary of key insight
- **Application Value**: How this helps future performance

#### Optional But Valuable Fields
- **Context**: What triggered this discovery
- **Supporting Details**: Additional relevant information
- **Suggested Location**: Where this fits in BRAIN structure
- **Cross-References**: Related existing knowledge

#### Writing Tips
- **Be concise**: Capture essence, not exhaustive detail
- **Be specific**: Concrete examples better than abstract concepts
- **Be practical**: Focus on actionable insights
- **Be clear**: Write for other agents to understand and use

## Submission Quality Guidelines

### High-Value Submissions Include
1. **Actionable Knowledge**: Other agents can immediately apply this
2. **Specific Context**: Clear situation where this knowledge applies
3. **Practical Examples**: Concrete instances of the learning in action
4. **Clear Benefit**: Obvious improvement this provides
5. **Appropriate Scope**: Neither too narrow nor too broad

### Common Rejection Reasons
- **Too Vague**: "I learned something about debugging" (not specific enough)
- **Already Known**: Information already well-documented in BRAIN
- **Not Actionable**: Interesting but doesn't improve performance
- **Poor Writing**: Unclear explanation or organization
- **Wrong Scope**: Either too specific to one case or too general

### Improvement Tips
- **Start Simple**: Better to submit clear, basic knowledge than complex, unclear insights
- **Include Examples**: Concrete cases make abstract concepts clear
- **Explain Context**: Help others know when to apply this knowledge
- **Focus on Change**: What will agents do differently with this information?

## Special Cases and Advanced Usage

### Urgent/Critical Submissions
For system-critical knowledge:
1. Use `priority-submission.md` template
2. Mark priority level clearly
3. Explain immediate impact
4. Include required actions for curator

### Cross-Agent Collaboration
When multiple agents discover something together:
1. One agent submits with attribution to others
2. Include all contributors in submission  
3. Note collaborative nature in context
4. Consider batch submission format

### Error Documentation
When documenting solutions to problems:
1. Describe the error clearly
2. Explain the solution steps
3. Include prevention strategies
4. Note any remaining concerns

### Process Improvements
When discovering better workflows:
1. Compare old vs. new approach
2. Quantify improvements if possible
3. Note any trade-offs or limitations
4. Include implementation guidance
